# 实时业务上下文接入

WeKnora 可以在知识库检索结果之外，为当前问答补充两类只读实时证据：

- 实体管理平台的当前设备/实体参数（通过实体知识图谱当前平台快照读取）。
- 交战规则系统中当前已启用规则集的 `ruleout.json`。

该能力同时作用于 `/knowledge-chat/:session_id` 和 `/agent-chat/:session_id`，不改变调用方的请求或 SSE 响应协议。

## 开启方式

功能默认关闭。部署时设置：

```env
REALTIME_CONTEXT_ENABLED=true
REALTIME_CONTEXT_GRAPH_BASE_URL=http://192.168.18.103:9707
REALTIME_CONTEXT_RULE_BASE_URL=http://192.168.18.103:9701
REALTIME_CONTEXT_CACHE_TTL=60s
REALTIME_CONTEXT_REQUEST_TIMEOUT=5s
REALTIME_CONTEXT_MAX_MATCHED_ENTITIES=20
REALTIME_CONTEXT_MAX_CONTEXT_CHARS=32000
SSRF_WHITELIST_EXTRA=192.168.18.103
```

服务启动时会异步预热快照；外部系统不可用不会阻塞 WeKnora 启动或导致整个问答失败。

## 读取范围

实体数据仅使用以下 GET 接口：

- `/api/sync/status`
- `/api/graph?freshOnly=true&limit=1000`

只有同步状态为 `success=true` 且 `source=platform` 的完整图谱才会作为新鲜证据。`source=sample` 或被截断的图谱不会被当作当前平台数据。

规则数据仅使用以下 GET 接口：

- `/api/v1/rule-base-rule-sets`
- `/api/v1/rule-base-rule-sets/{db_id}/rule-base-ruleout.json`

系统不会调用图谱同步、规则 preview/apply、PATCH、DELETE 等修改接口。通用交战规则问题读取全部启用规则集；问题明确包含规则集名称或编码时只注入匹配集合。

## 路由、缓存与降级

- 设备问题先按当前图谱中的实体 ID、实体名称、设备类型及状态/参数词确定性匹配。
- 只有多轮指代产生多个候选时，才使用当前问答模型对安全候选目录做一次结构化选择；模型输出不能选择目录之外的实体。
- 相机原理、设备教程等概念问题不会触发实时读取。
- 成功快照在进程内缓存 60 秒，并用 singleflight 合并并发刷新。
- 刷新失败但进程内存在历史成功快照时，快照可继续使用，但会标记为 `stale` 并显示最后成功时间，模型不得称其为“当前值”。
- 进程重启后没有历史快照且来源不可用时，仅使用知识库内容，并明确提示无法确认当前值。

## 数据安全

实体属性使用业务字段白名单。送入模型前会移除原始 JSON、认证/令牌/用户名、密码、内网 IP 与端口、服务地址、视频流和媒体地址；允许的嵌套业务 JSON 仍会执行递归敏感键和值过滤。实时证据始终作为“不可信数据”注入，不能覆盖系统指令。

知识库回答中的实时证据快照只保存经过脱敏的渲染内容用于当前消息审计；后续历史轮次仍重放原始用户问题，不会把旧实时快照当作新一轮事实。
