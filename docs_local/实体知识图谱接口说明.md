# 实体知识图谱接口说明

问答用于说明部署在 `192.168.18.103` 上的实体知识图谱如何访问、如何获取图谱数据，以及图谱里实体和关系的大致逻辑。

目前是从实体管理平台获取最近一分钟的实时数据，图数据库不保留历史数据。

## 1. 访问地址

| 服务 | 地址 | 说明 |
| --- | --- | --- |
| 前端图谱页面 | `http://192.168.18.103:9707` | 推荐入口，包含图谱展示、搜索、筛选、属性面板 |
| 前端问答页面 | `http://192.168.18.103:9707/qa` | 图数据库问答页面 |
| 前端同源 API | `http://192.168.18.103:9707/api/...` | 推荐给浏览器端调用，Next.js 会转发到后端 |
| 后端 API | `http://192.168.18.103:9706/api/...` | 后端直连调试入口 |
| Neo4j Browser | `http://192.168.18.103:9704` | Neo4j Web 控制台 |
| Neo4j Bolt | `bolt://192.168.18.103:9705` | Neo4j 驱动连接地址 |

前端代码默认请求同源 `/api/...`。浏览器打开 `http://192.168.18.103:9707` 后，前端请求 `/api/graph` 会由 Next.js rewrite 转发到后端服务，不需要在浏览器代码里硬编码 `192.168.18.103:9706`。

## 2. 前端如何获取图谱数据

前端主要调用：

```ts
fetch("/api/graph?freshOnly=true&limit=1000")
```

如果不走前端同源代理，也可以直接调后端：

```bash
curl "http://192.168.18.103:9706/api/graph?freshOnly=true&limit=1000"
```

推荐浏览器端使用前端同源地址：

```bash
curl "http://192.168.18.103:9707/api/graph?freshOnly=true&limit=1000"
```

### `GET /api/graph`

获取图谱节点和关系。

常用请求：

```bash
curl "http://192.168.18.103:9707/api/graph?freshOnly=true&limit=1000"
```

查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `freshOnly` | boolean | `true` | 是否只返回最近快照内的实体 |
| `limit` | number | `300` | 基础实体节点数量上限，最大 `1000` |
| `name` | string | 空 | 按实体名称或 `entityId` 搜索 |
| `template` | string | 空 | 按展示模板筛选，如 `TEMPLATE_PLATFORM`、`TEMPLATE_ASSET` |
| `specificType` | string | 空 | 按具体类型筛选，如 `UAV`、`DOCK`、`CAMERA` |

返回结构：

```ts
type GraphResponse = {
  nodes: GraphNode[];
  edges: GraphEdge[];
  is_truncated?: boolean;
};

type GraphNode = {
  id: string;
  labels: string[];
  properties: Record<string, unknown>;
};

type GraphEdge = {
  id: string;
  source: string;
  target: string;
  type: string;
  properties: Record<string, unknown>;
};
```

节点示例：

```json
{
  "id": "uav-201",
  "labels": ["Entity", "Platform"],
  "properties": {
    "entityId": "uav-201",
    "name": "无人机-201",
    "template": "TEMPLATE_ASSET",
    "displayTemplate": "TEMPLATE_PLATFORM",
    "displayKind": "Platform",
    "specificType": "UAV"
  }
}
```

关系示例：

```json
{
  "id": "5:xxx:87",
  "source": "uav-201",
  "target": "dock-DockAABBCCDD201",
  "type": "ASSOCIATED_WITH_DOCK",
  "properties": {
    "relationshipType": "associatedWithDock",
    "confidence": "confirmed",
    "sourceEntityId": "uav-201",
    "relatedEntityId": "dock-DockAABBCCDD201"
  }
}
```

前端渲染时：

- 用 `nodes[].id` 建节点索引。
- 用 `edges[].source` 和 `edges[].target` 找起点、终点节点。
- 用 `edges[].type` 显示关系类型和中文名称。
- 用 `node.properties` 和 `edge.properties` 展示属性面板。

最小前端调用示例：

```ts
async function loadGraph() {
  const res = await fetch("/api/graph?freshOnly=true&limit=1000", {
    cache: "no-store",
  });
  if (!res.ok) throw new Error(await res.text());
  const graph = await res.json();

  console.log("nodes", graph.nodes);
  console.log("edges", graph.edges);
}
```

## 3. 常用 API

### `GET /api/graph/summary`

获取图谱统计信息。

```bash
curl "http://192.168.18.103:9707/api/graph/summary"
```

返回示例：

```json
{
  "totalEntities": 107,
  "freshEntities": 107,
  "byTemplate": [
    { "template": "TEMPLATE_SENSOR", "count": 32 },
    { "template": "TEMPLATE_ASSET", "count": 30 }
  ]
}
```

### `GET /api/entities`

获取实体列表，适合搜索框、列表页使用。

```bash
curl "http://192.168.18.103:9707/api/entities?freshOnly=true&limit=100"
curl "http://192.168.18.103:9707/api/entities?name=无人机&freshOnly=true&limit=50"
```

查询参数：

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `freshOnly` | boolean | `true` | 是否只返回最近快照内实体 |
| `limit` | number | `100` | 最大 `500` |
| `name` | string | 空 | 按名称或 `entityId` 模糊搜索 |

返回结构：

```json
{
  "items": [
    {
      "id": "uav-201",
      "labels": ["Entity", "Platform"],
      "properties": {}
    }
  ]
}
```

### `GET /api/entities/{entity_id}`

获取单个实体详情和直接相关关系。

```bash
curl "http://192.168.18.103:9707/api/entities/uav-201"
```

返回结构：

```ts
type EntityDetailResponse = {
  found: boolean;
  entity: {
    id: string;
    labels: string[];
    properties: Record<string, unknown>;
    relationships: GraphEdge[];
  } | null;
};
```

### `GET /api/sync/status`

查看后端最近一次同步状态。

```bash
curl "http://192.168.18.103:9707/api/sync/status"
```

常见字段：

| 字段 | 说明 |
| --- | --- |
| `success` | 最近一次同步是否成功 |
| `source` | 数据来源，正常应为 `platform`，平台不可用且启用回退时可能为 `sample` |
| `entity_count` | 从实体管理平台获取到的实体数 |
| `node_count` | 写入/更新到 Neo4j 的实体节点数 |
| `relationship_count` | 当前图谱可见关系数 |
| `normalized_relationship_count` | 本次归一化产生的关系数 |
| `quality_issue_count` | 数据质量提示数量 |
| `error` | 同步失败时的错误信息 |

### `POST /api/sync/run`

手动触发一次同步。

```bash
curl -X POST "http://192.168.18.103:9707/api/sync/run"
```

正常情况下后端会自动定时同步；只有需要立即刷新数据时才需要手动调用。

### `GET /api/quality/report`

获取数据质量报告。

```bash
curl "http://192.168.18.103:9707/api/quality/report"
```

这个接口主要用于排查缺失关系目标、重复备用 ID、无效坐标等问题。

### `POST /api/qa/ask`

图数据库问答接口。

```bash
curl -X POST "http://192.168.18.103:9707/api/qa/ask" \
  -H "Content-Type: application/json" \
  -d '{"question":"有哪些无人机和机场有关联？"}'
```

请求体：

```json
{
  "question": "有哪些无人机和机场有关联？"
}
```

返回结构：

```ts
type QAResponse = {
  question: string;
  answer: string;
  cypher: string;
  rows: Record<string, unknown>[];
  usedFreshGraph: boolean;
};
```

后端会让 Qwen 生成只读 Cypher，并做安全校验。问答接口不允许写入、删除或修改 Neo4j 数据。

## 4. 图谱逻辑简述

### 数据流

```text
实体管理平台 HTTP/gRPC 只读接口
  -> FastAPI 同步服务
  -> normalizer 归一化实体和关系
  -> Neo4j 保存最新快照
  -> /api/graph 提供 nodes + edges
  -> Next.js + Sigma.js 前端渲染
```

当前系统只保留最新快照，不做历史版本保存。后台刷新应尽量保持静默，不打断用户当前选中节点或视角。

### 实体分类

后端以实体内部字段为准，不以接口文件名或接口筛选参数为准：

- `ontology.template`
- `ontology.specificType`
- `ontology.platformType`

前端展示主要看后端归一化后的：

- `properties.displayTemplate`
- `properties.displayKind`
- `labels`

前端展示分类：

| 展示分类 | 说明 |
| --- | --- |
| `Area` | 区域 |
| `Sensor` / `Camera` | 传感器、相机 |
| `Asset` / `Dock` / `Radar` | 资产、机场/机巢、雷达 |
| `Platform` | 平台、无人机 |
| `Model` | 算法模型 |
| `Route` | 航线 |
| `Rule` | 规则 |
| `AreaGroup` | 区域组辅助节点 |
| `ComputeServer` | 计算服务器辅助节点 |

有些实体平台里的无人机原始 `template` 可能是 `TEMPLATE_ASSET`，但只要 `specificType=UAV` 或 `platformType=PLATFORM_TYPE_MOBILE_UAV`，图谱展示时会归为 `Platform`。原始 `template` 会保留在属性里，方便追溯。

### 前端展示节点

前端可能会为了展示效果创建虚拟分类节点或虚拟边，这类节点只存在于浏览器内存中，不写入 Neo4j，也不是实体管理平台里的真实实体。

判断方式：

- 后端 `/api/graph` 返回的是 Neo4j 图谱数据。
- 前端虚拟节点通常带有 `virtual: true`、`displayOnly: true` 等属性。
- 做业务接口联调时，以后端 `/api/graph` 返回内容为准。

## 5. 联调建议

1. 先确认服务可用：

   ```bash
   curl "http://192.168.18.103:9707/api/sync/status"
   ```

2. 再拉图谱：

   ```bash
   curl "http://192.168.18.103:9707/api/graph?freshOnly=true&limit=1000"
   ```

3. 如果图谱为空，检查：

   - `sync/status` 的 `success` 是否为 `true`
   - `source` 是否为 `platform`
   - `entity_count` 是否大于 `0`
   - 前端是否请求了过窄的 `template`、`specificType` 或 `name` 参数

4. 如果浏览器跨域或访问异常，优先使用 `9707` 的同源 `/api/...` 地址，不要让浏览器直接写死 `9706`。

5. 如果需要后端排查，再直连：

   ```bash
   curl "http://192.168.18.103:9706/api/graph?freshOnly=true&limit=1000"
   ```
