# 自然语言转规则与算法读取接口文档

## 1. 接口地址

```text
POST http://192.168.18.103:9701/api/v1/rule-base-natural-language-rules
```

算法读取已生效规则：

```text
GET http://192.168.18.103:9701/api/v1/rule-base-rule-sets/{rule_set_db_id}/rule-base-ruleout.json
```

说明：

- 默认返回流式 SSE，`Content-Type: text/event-stream`。
- 如果调用方不想处理流式返回，可以使用 `?stream=false` 返回普通 JSON。

## 2. 调用流程

**自然语言转规则分两步**：

1. `preview`：生成规则理解和预览结果，不写正式规则表。
2. `apply`：确认预览结果生效，写入正式规则表。

调用方必须先调用 `preview`，拿到 `job_id` 和 `confirm_token` 后，再调用 `apply`。

后端会自动判断输入范围：

- 同时包含“防御圈层”“我方单位参数”“硬交战”“软交战”四类章节时，按完整规则全文处理。模型生成完整候选 `ruleout.json`，系统计算新增、修改和删除差异。
- 其他输入按增量修改处理，只变更自然语言明确提到的条目。

完整规则全文会删除新全文中不再出现的旧条目，因此必须先查看 `preview` 返回的差异清单，再决定是否调用 `apply`。

## 2.1 curl 示例

### 2.1.1 预览自然语言转换成的规则（流式输出）

```bash
curl -N \
  -X POST "http://192.168.18.103:9701/api/v1/rule-base-natural-language-rules" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "mode": "preview",
    "rule_set_code": "default",
    "natural_language": "1层：距离防御中心 0-1500米，内层防御圈。"
  }'
```

### 2.1.2 确认生效自然语言转换的规则

发送preview请求后，后端会返回：

"job_id": "0eec0f8b-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
"confirm_token": "preview-confirm-token",

在apply请求中需要携带这些参数：

```bash
curl -N \
  -X POST "http://192.168.18.103:9701/api/v1/rule-base-natural-language-rules" \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{
    "mode": "apply",
    "job_id": "<preview final 事件中的 job_id>",
    "confirm_token": "<preview final 事件中的 confirm_token>"
  }'
```



## 3. 生成预览（详细说明）

### 3.1 请求

```http
POST /api/v1/rule-base-natural-language-rules
Content-Type: application/json
Accept: text/event-stream
```

```json
{
  "mode": "preview",
  "rule_set_code": "default",
  "natural_language": "把 HR_003 调整为仅允许激光处置1层内的敌方无人机。"
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `mode` | 是 | 固定为 `preview` |
| `rule_set_code` | 是 | 已存在的规则集编码 |
| `natural_language` | 是 | 用户输入的自然语言规则文本，可以一次输入多条规则 |

### 3.2 流式返回事件

默认返回 SSE，每个事件格式如下：

```text
event: <事件类型>
data: <单行 JSON 数据>
```

事件类型：

| 事件 | 说明 |
| --- | --- |
| `step` | 当前处理步骤，例如读取规则集、调用模型、解析补丁、规则校验 |
| `model_delta` | 模型可见输出片段，用于前端实时展示生成过程 |
| `parsed` | 模型输出已解析为系统理解和候选补丁 |
| `validation` | 规则校验结果 |
| `final` | 最终完整响应，调用方应以此事件为准 |
| `error` | 处理失败，包含错误消息 |

注意：`model_delta` 不是隐藏思维链，只是模型实际返回的可见文本片段。

### 3.3 `final` 事件示例

实际 SSE 中，`final` 事件的 `data` 是一行 JSON。下面为了阅读方便格式化展示 `data` 内容：

```json
{
  "mode": "preview",
  "status": "preview_ready",
  "job_id": "0eec0f8b-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "confirm_token": "preview-confirm-token",
  "rule_set_code": "default",
  "summary": "系统理解：新增 1、2 层防御圈层配置。",
  "change_summaries": [
    "新增防御圈层 ring_1：0-500 米，意图为末端点杀层",
    "新增防御圈层 ring_2：500-1000 米，意图为动能毁灭层"
  ],
  "steps": [],
  "validation": {
    "valid": true,
    "errors": [],
    "warnings": []
  },
  "patch_operations": [],
  "preview_ruleout_json": {},
  "model_response": {},
  "error_message": null
}
```

关键字段：

| 字段 | 说明 |
| --- | --- |
| `status` | `preview_ready` 表示可确认生效；`preview_failed` 表示不能确认 |
| `job_id` | 预览任务 ID，确认生效时需要传回 |
| `confirm_token` | 确认令牌，只有校验通过时返回 |
| `summary` | 系统对自然语言规则的中文理解 |
| `change_summaries` | 面向用户的变更摘要 |
| `validation.valid` | 生成结果是否通过校验 |
| `validation.errors` | 校验错误，非空时不能确认生效 |
| `validation.warnings` | 校验警告，需要调用方或用户确认是否接受 |
| `preview_ruleout_json` | 预览后的算法 JSON |
| `model_response` | 模型原始 JSON；全文模式为完整候选契约，增量模式为候选补丁 |

### 3.4 规则条件结构

算法 JSON 中的 `condition` 支持两种形态。

原子条件：

```json
{
  "metric": "threat_distance_to_harbor",
  "operator": ">",
  "value": "@global_parameters.harbor_defense_rings.ring_1.max_m"
}
```

一层 AND 复合条件：

```json
{
  "and": [
    {
      "metric": "asset_speed_to_threat_speed_ratio",
      "operator": "<=",
      "value": 0.8
    },
    {
      "metric": "threat_away_from_asset_dot",
      "operator": ">=",
      "value": 0.5
    }
  ]
}
```

约束：

- `and` 至少包含两个原子条件。
- 当前只支持一层 `and`，不支持嵌套、`or` 或 `not`。
- `BETWEEN` 的 `value` 必须是两个边界值。

### 3.5 防御圈层修改示例

防御圈层编号不是硬规则或软规则 ID。输入中的“N层”映射到 `defense_ring` 的 `ring_N`；当该圈层已经存在时生成 `update` 操作。

输入：

```text
3层：距离防御中心 3000-4000 米，外层防御圈。
```

当前规则集已存在 `ring_3` 时，模型应生成以下候选补丁：

```json
{
  "operation": "update",
  "target": "defense_ring",
  "key": {
    "ring_key": "ring_3"
  },
  "values": {
    "min_m": 3000,
    "max_m": 4000,
    "intent": "外层防御圈"
  },
  "summary": "更新第3层防御圈"
}
```

### 3.6 增删改识别规则

增量输入会先按当前规则内容定位对象，再决定补丁操作。模型请求关闭思考模式，因此提示词中已经显式定义以下判定规则：

| 自然语言意图 | 输出操作 |
| --- | --- |
| 删除、移除 | `delete`，使用删除前的定位键，`values` 为空对象 |
| 停用、禁用 | `update`，设置 `status=disabled` |
| 启用、恢复 | `update`，设置 `status=enabled` |
| 修改、更新、调整、改为 | 当前对象存在时输出 `update`，`values` 只包含变化字段 |
| 新增、添加、创建 | 唯一键不存在时输出 `add`；唯一键已存在时转为 `update` |
| 未写操作动词但完整描述了一个新对象 | 唯一键不存在时按 `add` 处理 |

各类对象的定位方式如下：

| `target` | 定位键 | 支持的操作 |
| --- | --- | --- |
| `rule_set` | 空对象 `{}` | `update` |
| `defense_ring` | `ring_key`；“N层”映射为 `ring_N` | `add`、`update`、`delete` |
| `capability` | `asset` 和 `threat` | `add`、`update`、`delete` |
| `hard_rule` | `id`，例如 `HR_003` | `add`、`update`、`delete` |
| `soft_rule` | `id`，例如 `SR_010` | `add`、`update`、`delete` |

补充约定：

- 用户没有提供硬规则或软规则编号时，优先按当前规则中的唯一名称匹配；推断出的编号会在摘要中标记 `【推断】`。
- 新增硬规则或软规则且没有编号时，使用同类型当前最大数字编号加一，并保持三位补零格式。
- 改名或更换唯一标识时，`key` 保留修改前的定位键，新标识写入 `values`。
- 同一对象的多项更新合并为一个 `update`；多条不同对象指令分别生成操作，不得遗漏可定位项。
- 明确要求修改或删除但完全无法定位对象时，不会反向生成新增操作，摘要会说明无法定位。

## 4. 确认生效

### 4.1 请求

```http
POST /api/v1/rule-base-natural-language-rules
Content-Type: application/json
Accept: text/event-stream
```

```json
{
  "mode": "apply",
  "job_id": "0eec0f8b-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "confirm_token": "preview-confirm-token"
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `mode` | 是 | 固定为 `apply` |
| `job_id` | 是 | `preview` 返回的任务 ID |
| `confirm_token` | 是 | `preview` 返回的确认令牌 |

确认成功后，`final` 事件中的 `status` 为 `applied`，规则已经写入数据库。

## 5. 非流式调用

如果调用方不方便处理 SSE，可以加 `?stream=false`，返回普通 JSON。

```bash
curl -s \
  -X POST "http://192.168.18.103:9701/api/v1/rule-base-natural-language-rules?stream=false" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "preview",
    "rule_set_code": "default",
    "natural_language": "电子干扰：处置距离0-3000米。准备时间2s。打击次数1，重装填时间2s。对无人机基准拦截成功率10%。"
  }'
```

非流式返回的 JSON 结构与流式 `final` 事件中的 JSON 一致。

## 6. 算法读取已生效规则

调用方使用规则集数据库 UUID 获取当前启用数据：

```bash
curl -s \
  "http://192.168.18.103:9701/api/v1/rule-base-rule-sets/<rule_set_db_id>/rule-base-ruleout.json"
```

成功时 HTTP 200 直接返回纯 `ruleout.json`，不增加 `data`、`status` 等包装字段。

错误行为：

| HTTP 状态 | 含义 |
| --- | --- |
| `404` | 规则集不存在、已删除或已停用 |
| `422` | 当前启用条目不能组成合法算法契约，响应 `detail` 中包含错误路径 |

算法调用方必须同时支持原子条件和一层 AND 条件。不要绕过接口直接读取生产数据库表。

## 7. 版本约定

- 自然语言未明确修改版本时，沿用当前规则集的 `version`。
- 当前新规则基准版本为 `260620`；更新现有默认规则集时，先通过规则集 PATCH 接口设置版本，再执行完整文本 preview/apply。

开发环境需要验证真实 Qwen 输出时，显式执行：

```bash
cd backend
QWEN_API_KEY=<key> RUN_LIVE_QWEN_TESTS=1 uv run pytest -q -m live
```

普通测试不会调用外部模型。
